# Direct Japanese translation contract

Read the official authoring rules, language style guide, machine style policy and your own locale profile first. Each AI owns one distinct locale. Use Japanese-only translation packets; never use another locale as a semantic input or pivot. Reuse your own checked target-language wording for identical Japanese glossary definitions. Preserve respectful adult speech, exact address forms when they are the learning target, all qualifications, negation, uncertainty, speaker roles and clinical limits.

For new complete target files, explicitly set all six top-level approval flags (`humanReviewed`, `domainReviewed`, `nativeReviewed`, `nativeDeviceTested`, `rightsReviewed`, `releaseReady`) to `false`, as well as in the review; missing fields are not proof of approval or review.

Every batch remains `translated_ai_unreviewed`; human/domain/native/device/rights/release flags remain false until the relevant independent review actually happens. Atomic whole-week files are completion units. Scratch/draft work is not published as complete.

Before publishing, read the target as continuous teaching prose, not as a compressed outline. Faster parallel production does not authorize shortening conditions, actors, recipients, individual-plan requirements or reasons. Check source reporting instructions as a whole: what triggers reporting, what is reported, and to whom. A generic “report it” does not preserve an explicit Japanese medical-professional recipient. Correct clipped grammar even when every field and revision passes. Record semantic/style corrections in the locale's own review and refresh its actual file hash. Formatters must exclude IDs and source revisions; validate every binding again after the last formatting pass.

For paragraph edits, use the actual zero-based index from the Japanese packet and verify the existing source and target text before replacement. Dialogue turn numbers are not array indices: a scene description may occupy paragraph0. After the final write, compare each changed paragraph with its exact Japanese paragraph again, including the speaker and their role. Preserving array length does not detect a resident's statement accidentally replaced with a staff response.

Parallel locale owners use separate draft and handoff directories. A complete handoff pairs immutable target bytes with its actual review hash; the coordinator copies verified snapshots into an isolated integration checkout. If another workspace changes shared files, preserve that work and recover each owner's verified inputs rather than claiming the unknown edits were reviewed. Record superseding corrections explicitly. Japanese refinements discovered during translation are evidence-checked first, recorded separately from historical source closure, and propagated through refreshed Japanese-only packets. A packet from uncommitted Japanese inputs must identify its working-tree state and base commit rather than claim those bytes are already committed.

## Calendar weeks

`src/data/kaigo/japanese-master/translations/week-XX.LOCALE.json`:

- Top level: `version:1`, `language`, `translatedFrom:"ja"`, `status:"translated_ai_unreviewed"`, `humanReviewed:false`, `sections`, `lessons`, `questions`.
- Section: `heading`, exact parallel `paragraphs`, exact packet `sourceRevision`, `status`. If source has `figureCaptionsJa`, translate into `figureCaptions` with identical keys. Caption text participates in its source revision.
- Lesson: `title`, parallel `objectives`, `context`, `artCaption`, `sourceRevision`, `status`.
- Weekly question: `prompt`, parallel `options`, unchanged `correctIndex`, parallel `rationales`, `sourceRevision`, `status`. If the effective Japanese source has `readingJa`, translate as `reading`. Preserve explicit empty readings as `""`; omit the field when absent. The effective Japanese reading includes inherited original project-authored Japanese, not only fields present in the question draft.

Temporary packets can be regenerated after a canonical checkpoint using `scripts/write-kaigo-translation-packets.cjs` with `KAIGO_TRANSLATION_PACKET_DIR` pointing outside the repo and `TOKUTEI_QA_MODULES` set to installed QA dependencies. Preserve canonical source provenance and reload revised packets; do not merely update a stale translation's revision without comparing its meaning.

Each complete batch requires `reviews/TRANSLATION_WEEKXX_LOCALE.json`: counts from actual output, direct-Japanese/no-cross-translation declarations, source/translation hashes, semantic checks and open issues, approval flags. Register complete files with `scripts/sync-kaigo-direct-translations.cjs`, then run inventory, applicable weekly runtime and course-flow checks. A validator cannot certify meaning or naturalness.

## Full mock forms

After weekly content for the assigned locale, translate all12 effective Japanese mock forms directly. Canonical Japanese-only packet `full-mocks.ja.json` is generated by `scripts/write-kaigo-mock-translation-packets.cjs`. It applies recorded Japanese core corrections and Japanese rationale overlays before selecting source fields, so old source or locale text is not a substitute.

Target file `src/data/kaigo/japanese-master/mock-translations/mocks.LOCALE.json`:

- Same language/source/status/approval metadata as weekly batches, with a `forms` object keyed by unchanged form IDs.
- Each form: `title`, title `sourceRevision`, `status`, `questions` keyed by unchanged question IDs.
- Each question: `prompt`, parallel `options`, unchanged `correctIndex`, parallel `rationales`, `passage`, `figureDescription`, exact question `sourceRevision`, `status`.
- Source empty passage or figure description stays `""`; never invent missing material or recreate assets. Japanese furigana in the packet is a reading reference, not a field to translate or remove from Japanese.
- Preserve corrected effective Japanese meaning and answer position. The question revision includes prompt/options/index/rationales/passage/figure description/figure key. Missing or stale selected-locale translation must not use Vietnamese as fallback.
- Existing mock exam timing, navigation, attempt revisions and answer concealment stay intact. Translation belongs to submitted review under the existing explicit translation action.
- Review report `reviews/TRANSLATION_MOCKS_LOCALE.json` records actual form/question/option/rationale/caption counts, semantic checks, hashes and false approval flags.

Record the actual target file SHA-256 using the same `outputs:[{path,sha256}]`, `output:{path,sha256}`, or `translationPath`/`translationSha256` shape as your weekly review. Both inventories verify that hash after the final write. For new complete weekly batches, run `check-kaigo-translation-batch-runtime.cjs` with `KAIGO_TRANSLATION_BATCH`; it exercises the changed complete locale-week files. If local work has already been committed during reconciliation, set `KAIGO_TRANSLATION_BASE_REF` to the verified remote baseline so committed additions are still included. Per-checkpoint reports use distinct filenames, retain exact tested file hashes and preserve older runtime evidence. Concurrent continuations may set the same `KAIGO_TRANSLATION_REPORT_PREFIX` for batch runtime and checkpoint recording to keep report namespaces distinct; do not replace another continuation’s completed evidence. Japanese paragraphs rendered with furigana must be checked as exact base-text tokens plus readings and line breaks, rather than flattening both into a raw sentence. Actual completed mock translations require `check-kaigo-direct-mock-translations.cjs` for every question's submitted-review screen. Its report is separate from synthetic source-binding fixtures; no completed mock translation means no actual-language runtime pass.
